Root vs User Baru — Mana yang Dipakai?

Rekomendasi: login sebagai root hanya sekali di awal untuk membuat user baru (sendy) dengan hak sudo. Setelah itu, semua aktivitas — clone, build, edit config, restart service — dilakukan sebagai user sendy, memakai sudo hanya saat butuh hak admin. Ini standar praktik keamanan server production.

00 Persiapan📋 Checklist

Pastikan semua ini siap sebelum mulai, supaya proses tidak terhenti di tengah jalan.

  • IP VPS dan akses SSH (password root atau SSH key)
  • Domain sudah dibeli, dan Anda punya akses ke pengaturan DNS-nya
  • URL repository GitHub — dan Anda tahu apakah public atau private
  • Jika private: siapkan Personal Access Token, atau siap membuat SSH key baru
  • Akses ke server PostgreSQL yang dipakai (di VPS ini atau server terpisah)
  • VPS Ubuntu 22.04/24.04 LTS, RAM minimal 2GB (idealnya 4GB untuk build Vite)
Catatan penting: Panduan ini mengasumsikan database sudah dibuat manual lewat pgAdmin, dan php artisan migrate tidak akan pernah dijalankan — schema database dianggap sudah siap sebelumnya.
01 Login VPS & Membuat User Baru📍 Terminal lokal → VPS

Tujuan: Login pertama sebagai root, segera buat user baru dengan hak sudo. Root sebaiknya tidak dipakai untuk operasional harian.

📍 Jalankan di: Komputer lokal

bash
ssh root@IP_VPS_ANDA

📍 Jalankan di: Terminal VPS (sebagai root)

1 — buat user baru
adduser sendy
2 — beri hak sudo
usermod -aG sudo sendy
3 — (opsional) salin SSH key ke user baru
rsync --archive --chown=sendy:sendy ~/.ssh /home/sendy
4 — keluar, login ulang sebagai sendy
exit
ssh sendy@IP_VPS_ANDA

Cara mengecek berhasil

whoami
sendy
sudo whoami
root # setelah masukkan password sendy

Jika gagal

✕sendy is not in the sudoers file
✓Login lagi sebagai root, ulangi usermod -aG sudo sendy, lalu logout-login ulang.
02 Update Sistem & Firewall📍 Terminal VPS

Tujuan: Update sistem dan hanya buka port yang diperlukan (SSH, HTTP, HTTPS).

1 — update sistem
sudo apt update && sudo apt upgrade -y
2 — aktifkan firewall UFW
sudo apt install ufw -y
sudo ufw allow OpenSSH
sudo ufw allow 80
sudo ufw allow 443
sudo ufw enable

Cara mengecek berhasil

sudo ufw status
Status: active 22/tcp ALLOW Anywhere 80 ALLOW Anywhere 443 ALLOW Anywhere
Awas: Selalu ufw allow OpenSSH sebelum ufw enable — kalau kebalik, Anda bisa terkunci dari SSH.

04 Setup Akses GitHub📍 Terminal VPS

Tujuan: Menyiapkan cara VPS mengakses repo GitHub. Caranya beda tergantung public/private.

🟢 Skenario A — Repository PUBLIC

Tidak perlu autentikasi. Langsung clone nanti di Tahap 10:

git clone https://github.com/username/nama-project.git

🔴 Skenario B — Repository PRIVATE, Metode 1: Personal Access Token

Di GitHub: Settings → Developer settings → Personal access tokens → Tokens (classic) → generate dengan scope repo. Simpan token-nya, lalu clone dengan:

git clone https://TOKEN@github.com/username/nama-project.git
Jangan simpan token ini di file yang ter-commit ke repo. Token hanya dipakai sekali saat clone.

🔴 Skenario B — Repository PRIVATE, Metode 2: SSH Key (disarankan)

1 — generate SSH key di VPS
ssh-keygen -t ed25519 -C "deploy-vps"
2 — tampilkan public key
cat ~/.ssh/id_ed25519.pub

Copy seluruh output → GitHub → Settings → SSH and GPG keys → New SSH key → paste → Add SSH key.

3 — test koneksi
ssh -T git@github.com
Hi username! You've successfully authenticated, but GitHub does not provide shell access.

Jika gagal

✕Permission denied (publickey)
✓Pastikan public key benar-benar tersimpan di GitHub, dan Anda copy seluruh isi file .pub termasuk bagian awal ssh-ed25519.

08 Konfigurasi User PostgreSQL📍 Terminal VPS

Tujuan: Menyiapkan user PostgreSQL (sendy) untuk dipakai Laravel. Database TIDAK dibuat di sini — akan dibuat manual lewat pgAdmin di Tahap 9.

Jika PostgreSQL berada di server terpisah (bukan VPS ini), lewati instalasi dan buat user ini langsung lewat pgAdmin/tool client yang Anda pakai untuk akses server itu.

1 — install PostgreSQL (lewati jika sudah ada / server terpisah)

sudo apt install postgresql postgresql-contrib -y

2 — masuk shell PostgreSQL

sudo -u postgres psql

3 — buat user/role (dijalankan di dalam prompt psql)

SQL
CREATE USER sendy WITH PASSWORD 'sendy123';
\q
Penting soal keamanan: sendy123 hanyalah contoh. Untuk production sungguhan, gunakan password kuat (16+ karakter, kombinasi huruf/angka/simbol), dan jangan pernah commit password ke GitHub — hanya boleh ada di .env server, dan .env wajib ada di .gitignore.

Cara mengecek berhasil

sudo -u postgres psql -c "\du"
Role name : sendy ...
09 Membuat Database via pgAdmin📍 pgAdmin (lokal)

Tujuan: Ini bagian yang paling sering ditanyakan — cara menghubungkan pgAdmin ke server PostgreSQL di VPS, lalu membuat database di dalamnya secara manual.

Ilustrasi: Dialog "Register Server" di pgAdmin

Langkah-langkah lengkap

1Buka pgAdmin → klik kanan pada Servers di panel kiri → Register → Server...
2Tab General: isi Name bebas, misalnya VPS Production (hanya label, tidak memengaruhi koneksi).
3Pindah ke tab Connection (lihat ilustrasi di atas):
— Host name/address: IP VPS Anda (jika PostgreSQL di VPS yang sama), atau host database terpisah
— Port: 5432 (default PostgreSQL)
— Maintenance database: postgres (database bawaan untuk login awal)
— Username: sendy (user yang dibuat di Tahap 8)
— Password: password yang Anda set di Tahap 8
4Klik Save. Jika koneksi berhasil, server akan muncul di panel kiri dan bisa di-expand.
5Klik kanan pada Databases di bawah server tersebut → Create → Database...
6Isi Database name, misalnya nama_database. Di tab Definition, set Owner ke sendy agar Laravel punya hak akses penuh.
7Klik Save. Database baru langsung muncul di panel kiri.
Jika PostgreSQL berjalan di VPS yang sama dengan aplikasi Laravel, pastikan PostgreSQL mengizinkan koneksi dari luar (bukan hanya localhost) agar pgAdmin di komputer lokal Anda bisa connect. Ini butuh edit postgresql.conf (listen_addresses = '*') dan pg_hba.conf, serta membuka port 5432 di firewall — hanya lakukan ini jika memang perlu akses dari luar, dan sebaiknya batasi ke IP Anda saja demi keamanan.

Cara mengecek berhasil

Database baru terlihat di pgAdmin di bawah Databases, dan bisa dibuka (expand) tanpa error.

Jika gagal

✕Unable to connect to server: timeout expired
✓Port 5432 belum terbuka di firewall VPS, atau listen_addresses di postgresql.conf masih localhost. Sesuaikan lalu restart PostgreSQL: sudo systemctl restart postgresql.
✕password authentication failed for user "sendy"
✓Password salah ketik, atau pg_hba.conf belum mengizinkan metode auth yang sesuai (biasanya perlu baris md5 atau scram-sha-256 untuk koneksi dari IP luar).

📝 Catat nama database yang Anda buat — dipakai di Tahap 11 untuk mengisi DB_DATABASE di .env.

10 Clone Project dari GitHub📍 Terminal VPS
1 — siapkan direktori

2 — clone (pilih sesuai jenis repo)

🟢 Public:

git clone https://github.com/username/nama-project.git

🔴 Private (SSH):

git clone git@github.com:username/nama-project.git

🔴 Private (Token):

git clone https://TOKEN@github.com/username/nama-project.git
3 — masuk folder project
cd nama-project

Cara mengecek berhasil

ls -la
app/ artisan composer.json resources/ routes/ ...

Jika gagal

✕fatal: could not read Username for 'https://github.com'
✓Repo private tapi clone pakai URL public biasa. Gunakan URL dengan token/SSH sesuai Tahap 4.
11 Konfigurasi .env📍 Terminal VPS
1 — copy env example
cp .env.example .env
nano .env

2 — sesuaikan baris berikut

.env
APP_NAME="Nama Aplikasi Anda"
APP_ENV=production
APP_DEBUG=false
APP_URL=https://domain-saya.com

DB_CONNECTION=pgsql
DB_HOST=127.0.0.1
DB_PORT=5432
DB_DATABASE=nama_database
DB_USERNAME=sendy
DB_PASSWORD=sendy123
Wajib disesuaikan:
• APP_URL → domain asli Anda
• DB_HOST → jika PostgreSQL di server terpisah, ganti dengan IP/hostname server itu
• DB_DATABASE → nama database yang dibuat di pgAdmin (Tahap 9), bukan teks literal
• DB_PASSWORD → gunakan password kuat untuk production sungguhan

Simpan di nano: Ctrl+O → Enter → Ctrl+X.

Cara mengecek berhasil

cat .env | grep DB_
🔒 File .env tidak boleh ter-commit ke GitHub. Pastikan ada di .gitignore (biasanya sudah default di project Laravel baru).

14 Application Key & Cek Koneksi DB📍 Terminal VPS
1 — generate app key
php artisan key:generate
2 — cek koneksi database (read-only, aman)
php artisan tinker --execute="DB::select('SELECT 1 as test'); echo 'Koneksi database berhasil!';"

Alternatif — lihat daftar tabel yang sudah ada tanpa mengubah apa pun:

php artisan tinker --execute="print_r(DB::select(\"SELECT table_name FROM information_schema.tables WHERE table_schema='public'\"));"
❌ Jangan jalankan php artisan migrate di tahap ini atau kapan pun — schema database dianggap sudah lengkap via pgAdmin.

Jika gagal

✕SQLSTATE[08006] could not connect to server
✓Cek DB_HOST/DB_PORT di .env; jika server terpisah, pastikan firewall server DB mengizinkan koneksi dari IP VPS.
✕SQLSTATE[3D000] database does not exist
✓Nama DB_DATABASE tidak cocok dengan yang dibuat di pgAdmin Tahap 9.

16 Konfigurasi Nginx📍 Terminal VPS
1 — install
sudo apt install nginx -y
2 — buat konfigurasi
sudo nano /etc/nginx/sites-available/domain-saya.com
nginx config
server {
    listen 80;
    server_name domain-saya.com www.domain-saya.com;
    root /var/www/nama-project/public;
    index index.php;

    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }

    location ~ \.php$ {
        fastcgi_pass unix:/run/php/php8.3-fpm.sock;
        fastcgi_param SCRIPT_FILENAME $realpath_root$fastcgi_script_name;
        include fastcgi_params;
    }

    location ~ /\.(?!well-known).* {
        deny all;
    }

    client_max_body_size 20M;
}
3 — aktifkan & test
sudo ln -s /etc/nginx/sites-available/domain-saya.com /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl restart nginx

Jika gagal

✕duplicate listen options
✓sudo rm /etc/nginx/sites-enabled/default lalu sudo nginx -t lagi.
17 Konfigurasi PHP-FPM📍 Terminal VPS
1 — cek status
sudo systemctl status php8.3-fpm
2 — (opsional) tuning
sudo nano /etc/php/8.3/fpm/php.ini
upload_max_filesize = 20M
post_max_size = 20M
memory_limit = 256M
max_execution_time = 60
3 — restart
sudo systemctl restart php8.3-fpm

Jika gagal

✕Nginx menampilkan 502 Bad Gateway
✓PHP-FPM tidak jalan atau path socket salah. Cek sudo systemctl status php8.3-fpm dan sudo tail -f /var/log/nginx/error.log.
18 Queue Worker (Opsional)📍 Terminal VPS

Lewati jika project tidak menggunakan queue (QUEUE_CONNECTION=sync).

/etc/systemd/system/laravel-worker.service
[Unit]
Description=Laravel Queue Worker
After=network.target

[Service]
User=sendy
Group=www-data
Restart=always
ExecStart=/usr/bin/php /var/www/nama-project/artisan queue:work --sleep=3 --tries=3 --max-time=3600

[Install]
WantedBy=multi-user.target
sudo systemctl daemon-reload
sudo systemctl enable laravel-worker
sudo systemctl start laravel-worker

Jika gagal

✕Worker terus restart (crash loop)
✓sudo journalctl -u laravel-worker -n 50 --no-pager untuk lihat detail error.
19 Domain / DNS📍 Panel DNS Provider
  • Login ke panel DNS provider domain Anda
  • Buat A Record — Name: @ dan www, Value: IP VPS Anda
  • Simpan, tunggu propagasi (beberapa menit hingga 24 jam)

Cara mengecek berhasil

dig domain-saya.com +short
IP yang muncul harus sama persis dengan IP VPS Anda.
20 SSL / HTTPS dengan Certbot📍 Terminal VPS
⚠️ Prasyarat: domain harus sudah mengarah ke IP VPS ini (Tahap 19 sudah propagasi) sebelum menjalankan Certbot.
1 — install certbot
sudo apt install certbot python3-certbot-nginx -y
2 — jalankan certbot
sudo certbot --nginx -d domain-saya.com -d www.domain-saya.com

Isi email untuk notifikasi, setujui ToS, dan pilih Yes untuk redirect otomatis HTTP → HTTPS.

Successfully received certificate. Congratulations! You have successfully enabled HTTPS
3 — verifikasi auto-renewal
sudo systemctl status certbot.timer
sudo certbot renew --dry-run

Jika gagal

✕Challenge failed for domain
✓DNS belum ter-propagasi penuh, atau port 80 tertutup. Cek ulang Tahap 19 dan sudo ufw status.
21 Testing Production📍 Browser + Terminal VPS
  • Buka https://domain-saya.com — pastikan halaman muncul dengan gembok 🔒
  • Cek console browser (DevTools) — tidak ada error asset 404
  • Cek log Laravel: tail -f storage/logs/laravel.log
  • Cek log Nginx: sudo tail -f /var/log/nginx/error.log
  • Test fitur yang pakai database (login, submit form)
  • Cek redirect HTTP→HTTPS: curl -I http://domain-saya.com harus status 301/302
22 Update Aplikasi (git pull)📍 Terminal VPS

Tujuan: Alur ini dipakai setiap kali Anda push perubahan baru ke GitHub dan ingin men-deploy-nya ke production.

1 — masuk folder & maintenance mode
cd /var/www/nama-project
php artisan down
2 — tarik perubahan terbaru
git pull origin main

Ganti main sesuai nama branch production Anda.

3 — update dependency (jika ada perubahan)
composer install --no-dev --optimize-autoloader
npm install
npm run build
4 — cache ulang konfigurasi
php artisan config:cache
php artisan route:cache
php artisan view:cache
5 — restart worker (jika pakai queue)
sudo systemctl restart laravel-worker
6 — nonaktifkan maintenance mode
php artisan up
Sesuai aturan yang Anda tetapkan, php artisan migrate tetap tidak dijalankan di alur update ini. Perubahan struktur database (jika memang perlu) tetap dilakukan manual & terkontrol lewat pgAdmin.

Jika gagal

✕local changes would be overwritten by merge
✓Jangan edit file langsung di server (kecuali .env). Cek git status, lalu git stash atau git checkout -- file untuk buang perubahan lokal.
💡 Tips: untuk workflow lebih rapi, buat script deploy.sh yang menjalankan semua langkah di atas sekaligus, atau pertimbangkan tools seperti Laravel Envoy, GitHub Actions, atau Deployer.
23 Troubleshooting Umum📍 Referensi

502 Bad Gateway

✓sudo systemctl restart php8.3-fpm nginx

500 Internal Server Error

✓tail -n 50 storage/logs/laravel.log untuk detail penyebab.

Asset CSS/JS tidak termuat

✓Pastikan public/build/ ada isinya dan APP_URL sesuai domain sebenarnya.

npm run build gagal (out of memory)

sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab

Database connection refused

✓Cek pg_hba.conf dan listen_addresses di postgresql.conf agar mengizinkan koneksi dari IP VPS.

Sertifikat SSL tidak mau terpasang

✓Pastikan DNS sudah benar mengarah ke VPS dan port 80 terbuka, lalu ulangi certbot --nginx.
